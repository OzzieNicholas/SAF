已冻结的判定语义、口径和工程决策。政策见 D-014：每条决策的**结论与依据实质**一经接受不回改，被推翻只能新增一条并标注 supersede；失效路径、措辞等修辞层可以就地更新，使台账始终描述当前状态。

每条决策的格式：裁决、依据、状态。决策编号 D-0NN 是引用用的固定标识，代码、测试和文档里都用它指向这里。

## D-000  门先于码：结构化课题

- 裁决：SAF 采用“治理台账 + 验收门 + 实现包 + 产物目录”的结构化课题布局。操作真源是本台账和会跑的验收门，而不是散文同步；`docs/` 里的研究背景资料只读，不裁决项目状态。
- 依据：不建文档群、不靠散文同步规格；一个事实只有一个家。
- 状态：接受（目录细节见 D-006、D-033；范式本身仍然有效）。

## D-001  可达性主判据 = 语义 C（多方向直线插入无碰撞）

- 裁决：点 p 可达，当且仅当存在某个方向，工具沿直线从无穷远逼近 p 而不碰撞；任意方向都碰撞则不可达。弃用语义 A（局部可容纳，盲腔会误判为可达）；语义 B（连通路径）涉及运动规划，不作主判据，只作进阶讨论。
- 依据：[研究背景与设计](../docs/研究背景与设计.md) §4 的三判据对照（盲腔判例）；DeepMill [R6] 对不可达点的定义；IMF [R3] 对多朝向取碰撞测度同族。
- 状态：接受。

## D-002  基板不建模；工具从下半球逼近；oracle 只计零件本体遮挡（遮挡下界）

- 裁决：碰撞场景不放地面或基板；对下朝支撑接触点，工具可从外侧（下半球）任意方向逼近；oracle 仅以零件本体几何为遮挡体。给出的是遮挡**下界**。
- 依据：语义 C 下若引入基板，会挡住整个下半球，使所有下朝面翻为不可达、标签性质反转；本课题定位为几何代理，工具近似手工或打磨（常在拆板后）；这是“遮挡下界”局限的显式化。
- 状态：接受（须写入论文局限：只计零件本体遮挡，未建模基板、支撑间相互遮挡与移除顺序）。

## D-003  oracle 实现口径 = 体素距离场腐蚀（工具半径摊销）+ 边界带精确胶囊细化

- 裁决：在体素距离场上计算。对实体做一次无符号距离变换，阈值 r 得到“腐蚀自由场”；点 p 沿方向 v 可达，当且仅当从 p+r·v 沿 v 到无穷远的射线整段落在腐蚀自由场内（即栅格上的 ray-march）。半径对所有点一次摊销。栅格分辨率分不出的边界带用精确的胶囊—网格求交细化（见 D-020）。禁止用裸网格逐点逐方向的胶囊求交作为主口径。
- 依据：与 IMF 的 Minkowski 腐蚀同源；把预算从“每点每方向一次胶囊测试”压成“一次距离变换 + 廉价栅格步进”，GPU 友好；边界带机制解释了标签里的“边界不确定”。
- 状态：接受（连续数值见 D-021）。

## D-004  第一版标签 = 二分类可达 / 不可达

- 裁决：用二分类；分档可达性、截断余量、连续有符号余量属进阶，第一层不稳定就不进更高层。
- 依据：二分类更易审核、更易与基线比较、能形成闭环，不会被追问余量的物理意义。
- 状态：接受（方向级输出见 D-024，二分类是它的 any 归约）。

## D-005  工具 = 球模型，方向灵活

- 裁决：主实验用球模型，逼近方向相对灵活（近似手工或打磨）。方向受限的工具（特定角度的铣削或切割头）把判据收窄为“在受限方向集内是否存在无碰撞直线插入”，作为进阶变体，不进当前范围。
- 依据：[研究背景与设计](../docs/研究背景与设计.md) §4.2、§4.3。
- 状态：接受。

## D-008  半径单调性证伪：点接触语义 C 下不成立（经验发现）

- 裁决：不把“半径单调”（r 增大，不可达集只增不减）当作 oracle 不变量；`test_properties::test_radius_monotonic` 不接绿（跳过）。该趋势只在受限腔体几何上作为标签质量审核的一项检查。
- 依据：对随机占据实测，逐点违反率为 44/200，暴力参考也违反 33/300，所以不是体素实现的问题而是语义本身的性质：点接触下大球能从更远处够到开阔面上的点，小球反因贴近表面被挡。受限的已知答案件（盲腔）上仍然直觉成立。
- 状态：接受（语义 D-001 不变，只如实记录并不接这条不变量）。

## D-009  网格前端口径：mesh → 占据（igl 快速缠绕数）；多实体用 numpy 堆叠

- 裁决：真实网格转占据栅格，用 `igl.fast_winding_number(V, F, 栅格中心) > 0.5` 判内外。多实体件用 numpy 手动堆叠顶点和面索引（缠绕数对不相交实体可加），**禁用** `trimesh.util.concatenate` 和 `apply_translation`——本环境下二者会原生崩溃。默认分辨率和 pad 见 D-021；占据以 (occ, lo, pitch) 表达，查询点世界坐标经 `world_to_voxel` 转成体素坐标交给 oracle。
- 依据：实测 igl 判内外正确（盒子填充率与解析值一致）；全链路 盒子 → 占据 → oracle 能复现“下朝面可达、两盒窄间隙不可达”；无布尔库，不能挖洞；trimesh 的 concatenate 与平移会稳定崩溃，numpy 堆叠稳定。
- 状态：接受。

## D-010  支撑接触区提取：下朝悬垂面 S(P, d) = { n·d̂ < −cos θc }

- 裁决：给定网格 (V, F) 和构建方向 d，支撑接触区代理是外法向 n 满足 `n·d̂ < -cos(θc)` 的面集合，θc 为悬垂角阈值（见 D-021）。外法向用 numpy cross；用悬垂面质心作接触点；评价可达性时，质心沿外法向外移若干体素到自由侧作为查询点（外移口径见 D-028）。S 随 d 变化。
- 依据：外法向与 d 的夹角超过阈值，等价于局部倾角低于自支撑临界角；探针验证 cross 法向与 trimesh 外法向一致，阈值附近干净。
- 状态：接受。

## D-011  尺度不变经整数上采样证伪：分辨率依赖，非严格不变量（经验发现）

- 裁决：不把“尺度不变”（整数上采样 k 倍，标签不变）当作 oracle 不变量；`test_properties::test_scale_invariance` 不接绿（跳过）。真实网格的分辨率稳定性由 D-020 的细化与 D-025 的审核处理。
- 依据：Hypothesis 找到反例——粗网格判可达，2 倍上采样后判不可达，且 r±ε 邻域都不一致。根因是粗网格漏判欠分辨的薄特征。所谓“尺度不变”实际是分辨率稳定性，粗网格不够细时会真错。
- 状态：接受（语义 D-001 不变）。

## D-018  命门须据实签收，自动化不得关闭命门

- 裁决：命门是判定语义、真实网格上的标签质量、以及企业隔离与不过度声称的边界纪律。自动化（含智能体循环）只在独立可信的门（构造即知答案、差分对拍等，真值不依赖被测物）下迭代到绿，不得关闭命门，防止“假绿”。未经签收的真实网格标签不进训练集。因课题无外部评审，签收的证据由量化审核提供（见 D-025）。
- 依据：D-011 的教训——以为是不变量、其实不是，此前的绿是运气。
- 状态：接受（证据机制由 D-025 改为量化审核）。

## D-020  边界带精确胶囊—网格细化落地（有网格三态、无网格二分不变）

- 裁决：实现 D-003 的边界带细化。体素腐蚀 ray-march 给出每个方向的最小净空 clearance。**无网格**（程序化合成占据）：二分——任一 clearance > r 即可达，与细化前逐比特一致。**有网格**（真实 CAD，传入 V、F、lo、pitch）：三态——clearance > r+ε 明确可逃逸 → 可达；含糊方向（clearance > r−ε）交精确胶囊测试（半无穷射线到三角网格的最小距离 ≤ r_world，无离散误差）定夺，任一无碰撞 → 可达；皆碰 → 不可达。细化给真值而非隔离，所以不产出 UNCERTAIN。ε 见 D-021。
- 依据：真实 CAD 在物理临界点（工具半径约等于局部特征尺度）上，纯体素标签随分辨率不收敛（固定世界查询点，分辨率 48、96、192 之间约 10–13% 翻转）。细化后同样样本在三个分辨率上的标签一致率为 1.000（纯体素为 0.865 / 0.899）。因此低基础分辨率加细化即可得到分辨率稳定的训练级标签，缓解单卡预算。语义 D-001、D-002 不变。
- 状态：接受（守护性质 `test_capsule`；属命门相关，真实标签按冻结参数重采后须经 D-025 审核）。

## D-021  冻结标签口径的连续数值

- 裁决：冻结以下数值，登记在 `configs/oracle_params.yaml`，代码一律通过 `support_accessibility.runtime.frozen_params` 读取，不再硬编码：全局候选方向数 128（取下半球后 64 个）；边界带宽 ε = 1.5 体素；占据分辨率 48（加精确细化）；工具半径 0.05（归一尺度，零件最长边为 1）；悬垂阈值 45°。改动须新增 supersede 条目。
- 依据：标签质量门（六项趋势加 D-020 细化）通过后冻结。真实几何上方向数 128 对 256 的标签一致率为 0.982（64 个只有约 0.95）；D-020 令分辨率 48、96、192 的标签一致，所以低基础分辨率即可训练级；半径 0.05 能让“射线可见但工具够不到”的现象显现。
- 状态：接受（守护：`tests/unit/test_data_paths.py::test_frozen_parameters_match_the_registered_values` 与 `tests/acceptance/test_governance.py` 的冻结参数键检查）。

## D-022  D-020 实现加固（野网格可跑）与 Thingi 接入采样上限

- 裁决：为 Thingi10K 野网格落地三处实现层改动，判定语义与口径不动：
  1. **预计算网格常量**：`precompute_mesh(V, F)` 每模型只算一次三角、质心、外接半径和顶点包围球，供所有点和方向的细化复用（包围球给出的 far 不小于精确值，只多覆盖同一半无穷射线，逐比特等价）。
  2. **跳过退化三角**：胶囊求交跳过零面积三角（重合或共线顶点会令 Ericson 最近点原语除零）；它是度量零面，无面可触，对干净 CAD 的标签零改动。
  3. **Thingi 采样上限**（测试集构建，非 oracle 口径）：每模型接触点上限 400（确定性无放回子采样，是逐点 F1 的无偏估计）；面数上限 80000（超高面件跳过以控制剪枝成本）。Thingi 恒为 test、不进训练，所以这些上限不触及标签口径冻结。
- 依据：H5 需要在野外网格上评估形状条件预测的跨域鲁棒性；上限让单卡预算可解。
- 状态：接受（守护 `test_capsule` 的 precompute_equiv 与 degenerate_skip、`test_thingi` 的 `_select_points`）。

## D-024  方向级可达性场：oracle 输出扩为每方向可达向量（extend D-004）

- 裁决：把 oracle 输出从点级二分扩为方向级场。对固定的下半球逼近方向集（`lower_hemisphere_dirs(n)`，n = 128 时 D = 64 个方向），每点输出每个方向是否可达的向量。判据分毫不变（同 D-001..D-003、D-005：clearance > r，有网格时含糊带交精确细化），只是不做 OR 归约。接口：`oracle.direction_labels(p, r)` 与 `decide_direction_labels`；模型侧 `ConvONetLite` 加 `out_dim`（= D；默认 1）。**核心不变量**：`any(direction_labels) == (label == ACCESSIBLE)`——二分口径是本场的 any 归约。
- 依据：项目命名里的“Field（场）”本义就是方向级；点级二分是其特例。判据和二分语义都没动，只扩了输出粒度，所以是 extend 而非 supersede。逐方向多数类基线 F1 为 0，说明模型在稀有的“被挡方向”上的得分不靠先验。
- 状态：接受（守护 `test_direction_field`；方向级标签若作为头号训练源，训练前由作者据实签收，同 D-018）。

## D-025  真实标签有效性审核客观化：量化审核替代人工视觉签收（supersede D-018 的证据机制）

- 裁决：命门的证据机制从“作者视觉审审计图”改为**客观量化审核** `experiments/label_audit.py`，结果写入数据集的 `dataset.json`（`label_audit` 块）并据此置 `human_signoff`。三条可量化性质：
  1. 差分一致：纯体素 oracle 对暴力参考，在 D-003 边界带容忍下的 robust 不一致率不超过 0.01；
  2. 跨分辨率稳定：分辨率 48 与 96 的标签一致率不低于 0.95；
  3. 分布合理：不可达占比在 [0.01, 0.9] 内，且存在两类件。
  细化层由 `test_capsule` 的精确原语守护。人的角色降为一次性认可这套阈值（本条即认可）。
- 依据：oracle 是显式的几何代理，物理精确是非目标；论文诉求（面积弱相关、半径要紧、神经预测代理）对小幅标签噪声鲁棒。视觉审核主观、不可复现、易造假绿（曾有一次性扩量脚本写下 `human_signoff = True` 却无审计图）。再拔高到分辨率 96 重标会破坏 D-021 的冻结、耗时数小时、重跑全部实验，却换不来结论变化。D-018 的实质（须有硬证据、不得假绿）不变。
- 状态：接受（守护 `experiments/label_audit.py` 与 `test_differential`、`test_capsule`、`test_label_quality`；审核数值见结果账本）。

## D-026  预算门与回归门

- 裁决：
  1. **预算门**：用冻结的实测单点单方向耗时 D0（纯体素口径）乘以规模参数（8625 件 × 38 点 × 128 方向 × 1 个半径）外推全量构建时间，不超过上限 4 小时则通过。门用冻结 D0 而不是现场计时，所以与机器速度无关；它守护的是**规模膨胀**，不代表真实构建成本。D0 换机或改口径重测须更新常数并记录。
  2. **回归门**：`experiments/regression_check.py` 训练神经二分模型与射线可见性基线，在留出件上逐件配对 F1，对件做 bootstrap 得到配对差的 95% CI；下界大于 0 即神经显著不劣于最强几何基线 → 通过。结果写入 `artifacts/runs/regression_check/result.json`，门读取它裁决；产出须自带数据摘要，数据变化后视为陈旧 → PENDING。
- 依据：两门在指标固化后启用。回归门读实验产出而不是零安装重训：torch 与数据不在零安装的门内，读机器产出是诚实活检（无产出即 PENDING，不造假绿）。
- 状态：接受（不触及判定口径）。

## D-028  网格前端加固（extend D-009、D-010）：确定性、栅格维度修正、缠绕安全外移

- 裁决：判定语义不动，对网格前端做三处实现层加固：
  1. **ingest 确定性**：目录遍历排序（`sorted(os.walk(...))`），使跨机器产出顺序稳定，`split_by_model` 的分配可复现；
  2. **栅格维度修正**：`ns = max(1, ceil((hi − lo)/pitch − 1e-9))`——消除最大轴的浮点过冲，零厚度轴不塌成空栅格；
  3. **缠绕安全外移**（`mesh.nudge_to_free`）：占据用对缠绕稳健的 igl 缠绕数，下朝面法向用对缠绕敏感的 `np.cross`，二者不一致时旧口径“质心沿外法向 +2 体素”可能把查询点落进实体。新口径按落点分三态：**free**（+n 自由，同旧）；**confined**（+n 与 −n 都是实体，是深窄槽或窄隙里的真下朝面 → 保留，oracle 判不可达，保住稀有的不可达正类）；**flipped**（+n 实体但 −n 自由，法向翻转，是被悬垂判据误纳的伪下朝面 → 丢弃并计数，写入 `dataset.json` 的 `nudge_discarded_flipped_normal`，不静默删除）。命门审核的跨分辨率腿同步走这条外移（审的就是 ingest 实际产出的点）。
- 依据：旧口径下约 5.8% 的点落在实体内，其中“实体内却判可达”的点高度指示翻面伪下朝面（新口径丢弃），“实体内判不可达”的点多为真窄隙正类（新口径保留），所以新口径剔伪保真。语义 D-001..D-005、D-020 不动。
- 状态：接受（守护 `test_mesh_frontend`；数据集已按本口径物化并重新签收，数值见结果账本）。

## D-033  目录、路径、命名与入库策略的整体重整

- 裁决：
  1. **目录**：论文下游包是顶层 `paper/`（`manuscript/`、`pipeline/{figure_scripts,audits}`、`figures/`、`evidence/`、`outputs/`、`build/`）；可复现实验放 `experiments/`（语义命名，每个脚本写入 `artifacts/runs/<脚本名>/result.json`，并提供 `--out`）；`tools/` 只放数据集构建、全量实验复现入口 `reproduce_experiments.py`、缓存清理和布局检查；路径解析、运行记录和冻结参数读取放包内 `support_accessibility.runtime`，脚本不再自行改 `sys.path`。
  2. **路径**：仓库内不写盘符绝对路径。数据位置按“命令行参数 > 环境变量 `SAF_DATA_ROOT` > 不入库的 `configs/paths.local.yaml` > `configs/paths.yaml` 的相对默认值”解析，数据根默认是仓库内被忽略的 `data/`。
  3. **命名**：处理后数据集标识改为 `fusion360`、`procedural`、`thingi10k`，目录直接是 `processed/<名>/`，不再有运行名；逻辑引用写成 `dataset://<名>`。论文引用的实验以脚本名为证据键。
  4. **入库策略**：论文成品图、证据清单、源稿、`references.bib` 入库；论文 PDF、处理后数据集、`artifacts/` 不入库（二进制随重建反复膨胀历史，而数据集可由公开数据确定性重建）。
  5. **论文单一源**：`论文正文.md` 是唯一人工维护的源稿（含图、表、公式、参考文献列表），LaTeX 由 `markdown_to_latex` 渲染；正文数值由 `numeric_claims.yaml` 逐条登记并与证据清单核对。
  6. **不引入的机制**：提交与分支规范的强制检查及其 hooks 与 CI；`project.json` 类通用清单；未决册；模拟审稿记录与完整性 sidecar；Zotero 集成；“旧目录不得复活”类检查；阶段计划类背景文档（其内容并入 `研究背景与设计.md`）。D-013、D-019、D-029 中与上述机制相关的文字由本条取代。
  7. **文档与命名规范**：治理与参考文档用中文语义名；文档不含日期、版本号和流水记录。规则写入 `工程规范.md`，由 `tools/check_structure.py` 机检（目录白名单、命名、依赖方向、盘符绝对路径、文档日期与文档名）。
- 依据：结构混杂（脚本以编号命名、论文代码与成品混放、残留与绝对路径、正文双份手工同步、证据数字与正文各写各的）使复现和维护成本高；绝对路径使项目无法在另一台机器上运行；与实际提交风格不符的检查会成为失效的门。把可移植、无残留、单一事实来源变成会红的检查，比靠约定更可靠。
- 状态：接受（判定语义 D-001..D-005 与冻结参数未动；由 `test_governance::check_repository_structure` 与 `paper_pipeline` 测试守护）。
